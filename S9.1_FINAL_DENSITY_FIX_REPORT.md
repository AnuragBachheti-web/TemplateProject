## Changes

1. **`LabelValueListBlock`'s primary-value resolver rewritten to be data-driven.** No more fixed
   `value/note/detail/amount/pct` list deciding "is there a value at all" — that priority chain
   still wins first (unchanged behavior for existing fixtures), but when none of it matches, the
   first remaining non-decorative field is promoted to the primary value instead of being left
   blank. Remaining fields are then split by length: short ones (≤18 chars — a percentage, a count)
   join the primary value inline on the same line; long ones (real prose — a `why`/`note`
   explanation) keep their own secondary line. Fixes `{label, meta}`, `{label, n, w}`,
   `{label, key, numeric}` uniformly — no per-field special case, and `moveBar` specifically needed
   zero additional code beyond this.
2. **`cols`-style column/row metadata is suppressed at generation time when it provably describes a
   sibling table.** New `findMetadataDescriptorSlots` in `classifyBlocks.js`: every item must have
   both a `key` and a `label` field, AND a real sibling `table` block's own resolved columns must
   overlap ≥80% of those `key` values — a structural match, never a name/workflow guess. Wired into
   `generateManifests.js` before section planning, so a suppressed block never occupies a slot,
   never needs a runtime opt-out, and simply isn't generated.
3. **`TextBlock`'s compact row no longer overflows its container.** The value span had `shrink-0`
   next to `truncate` — self-defeating, since `shrink-0` is exactly what prevents `truncate` from
   ever having anything to do. Now: label gets `max-w-[45%] shrink truncate`, value gets
   `flex-1 min-w-0 truncate` — both genuinely participate in flex sizing, so neither escapes the row
   and neither over-truncates to compensate for the other refusing to shrink.
4. **Decorative-key filtering rewritten from a trailing-suffix regex to a camelCase word-split
   check**, consolidated into one shared runtime module (`decorativeKeys.js`) used by
   `ItemQueueBlock`, `LabelValueListBlock`, and `TableBlock` (previously three independent, drifting
   copies). Catches `dotInner` ("dot" isn't the last word) the old suffix-only regex missed.
   `classifyBlocks.js`'s own generation-time copy got the identical fix, plus two new **value**-shape
   patterns (an icon-glyph string `fa-solid fa-...`, a CSS border/divider shorthand
   `1px solid var(--...)`) added to `isPureStyleValue` — this is what stops a **top-level** field
   like `pushAllIcon`/`armBtnIcon`/`divider` from ever becoming a manifest block at all, since
   top-level filtering was always value-based, never key-name-based, and no per-item decorative-key
   check ever ran on a top-level scalar.
5. **A lone, heuristically-grid-eligible scalar with no sibling to actually group with** (e.g.
   `Display Mode` alone on Analyze) now renders as a lightweight tinted strip
   (`rounded-lg bg-rf-surface-sunken`) instead of a full `GridPanel` card. A 2+-item grid row is
   completely unaffected — this only fires for a genuine run-of-one.
6. **Hero eligibility is semantic first, length second.** `role === 'hero'` (a manifest-level
   judgment already made once, knowingly) now bypasses `HERO_MIN_LENGTH` entirely; the bare
   slotName-vocabulary fallback (no explicit `role`) still requires the length safety net, since
   it's a weaker, uncurated signal.
7. **`TableBlock` gained a scroll-shadow affordance.** A ref + scroll listener toggle two
   `aria-hidden`, `pointer-events-none` edge-fade overlays, shown only on the side there's genuinely
   more content, gone the instant that edge is reached — verified rendering correctly via a real
   scroll on `S9.16/Decide`'s "Modes" table (881px content in an 834px container).
8. **`StageSections`'s outer grid only reserves the 300px rail column when a rail actually exists.**
   Previously the 2-column template applied unconditionally, so a stage with no rail content kept
   the same narrower main width as one that had a rail, for no reason.

8. No-rail pages reclaim horizontal space — **PASS** (verified: `S9.1/Reason`'s body grid no longer

## Architecture Safety

Explicitly confirmed NOT rewritten, re-verified by direct inspection after this pass:

- **`composeSections.js`'s region-resolution order** (block override → section → legacy → main) —
  untouched.
- **`ComposedPanel`** — untouched (Decide's hero panel still fuses via the exact same mechanism).
- **`GridPanel`** — untouched for any row with 2+ members; only a genuine 1-item run now takes a
  different, new, additive path (`LoneScalarStrip`).
- **`RailPanel`** — untouched.
- **The block registry** (`blocks/index.js`) — untouched.
- **The manifest schema** (`role`/`region`/`layout.group`/`layout.span`/`headline`) — untouched;
  `findMetadataDescriptorSlots` removes blocks from the array before any of these fields are ever
  assigned, it doesn't add a new field to the schema.
- **The binding/validation pipeline** (`resolveBinding.js`, `blockTypes.js`, `validateManifest.js`)
  — untouched.
- **No workflow-specific conditional was introduced anywhere.** Every rule added this pass is keyed
  by data shape (column-count threshold, `key`+`label` descriptor shape, camelCase word match,
  value-pattern regex) or by manifest-declared semantics (`role`) — never by workflow code or stage
  name. Confirmed by construction (every new function takes `blocks`/`dataObject`/a bare string,
  never a workflow code) and by the cross-workflow verification above (S9.4, S9.6, S9.10, S9.16 all
  benefited from the identical, unmodified rules S9.1 did).

## Remaining Issues

Genuinely still present, not fixed by this pass, and not claimed to be:

- **S9.1/Execute grew by 77px** — explained above; a deliberate readability trade-off, not a defect,
  but listed here for honesty since it's the one route that didn't shrink.
- **Wide tables (Modes/Slate/Grid, 6–8 columns) still don't fit inside the ~836–900px main column**
  — they now have a visible, working scroll affordance instead of a silent clip, but the underlying
  column count vs. column width tension itself is unresolved; the forensic audit's own fix plan
  named "give wide tables a visible affordance," not "make every table fit," as the target for this
  pass, and that's what was built.
- **`focusTitle`/`focusMeta`/`focusFooter`-style rail microcopy** (flagged in the earlier
  architecture report as belonging with a main-column widget, not the generic rail) is unchanged —
  out of scope for this pass, which targeted the forensic audit's specific findings.
- **No live Claude-in-Chrome verification** — every screenshot and measurement in this report comes
  from a real, separately-launched headless Chromium, not the connected browser tool, because the
  extension itself was not connected in this environment. Stated plainly, not glossed over.
- **`extraction/audit.js` itself was not updated** to understand the new intentional suppressions —
  it will keep reporting the same 42 "data loss" false positives on every future run until (if ever)
  someone teaches it about `findMetadataDescriptorSlots`. Left alone deliberately (out of scope: the
  task listed files to inspect, and `audit.js` wasn't one of the "primary" files, and modifying a
  diagnostic tool wasn't part of the prescribed fix plan).

This pass is a measured, verified improvement against the forensic audit's own findings — not a
claim of pixel-perfect reference fidelity, and not "production ready" merely because tests pass.
